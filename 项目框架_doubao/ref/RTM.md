# RTM — 需求追踪矩阵（Requirements Traceability Matrix）

> **定位**：**动态维护**需求从提出到实现、验证的**全链路追踪状态**。
> **关联**：需求 ID 与 [requirements.md](./requirements.md) 保持一致；实现状态与 [progress.md](./progress.md) 联动；测试用例见 [test_plan.md](./test_plan.md)（如已拆分）。
> **更新频率**：中频（需求变更、实现推进、验证完成时更新）。

## 3. 状态定义

- **实现状态**：未开始 → 进行中 → 已实现 →（变更时回退）→ 已验证。
- **验证状态**：未验证 / 通过 / 失败（失败时在 issues.md 登记，并回退实现状态）。
- **优先级**：P0 必须满足（核心/安全/合规）、P1 应当满足、P2 可以延后。

## 4. 维护规则

- 需求变更：先更新 requirements.md，再同步本矩阵（新增/删除/修改 ID 及状态）。
- 实现推进：与 progress.md 同步更新，保持两个文档状态一致。
- 验证完成：填入验证方法与结果；未验证的需求不得标记为「已验证」。
- 覆盖率检查：本矩阵覆盖 requirements.md 全部需求 ID；出现未登记 ID 即为缺口。
