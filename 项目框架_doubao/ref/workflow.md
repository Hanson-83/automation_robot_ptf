## 2. 工作流总览（阶段流）

```text
调研/可行性 → 需求梳理 → 方案设计 → 规划 → 具体设计 → 开发构建 → 测试 → 部署 → 运维/迭代
```

| 阶段 | 目标 | 主要活动 | 出口产物 | 更新文档 | 负责角色 |
|---|---|---|---|---|---|
| 0 调研与可行性 | 摸清问题与可行路径 | 资料检索、技术验证、方案对比 | 可行性结论/专题报告 | doc/<topic>_report.md | 调研 Agent |
| 1 需求梳理 | 明确范围与验收标准 | 干系人访谈、需求条目化 | requirements.md | requirements.md、RTM.md | 需求 Agent |
| 2 方案与规划 | 定方案与计划 | 架构决策、任务分解、排期 | plan.md、design_spec.md、execution_plan.md | plan.md 系列 | 方案/规划 Agent |
| 3 开发构建 | 实现系统 | 编码、集成、自测 | 代码、构建产物 | progress.md、technical_manual.md | 开发 Agent |
| 4 测试 | 验证质量 | 用例执行、缺陷修复 | 测试报告 | test_plan.md、issues.md、RTM.md | 测试 Agent |
| 5 部署发布 | 上线运行 | 发布、监控、回滚预案 | 部署记录 | operation_log.md、environments.md | 部署 Agent |
| 6 运维/迭代 | 稳定运行与演进 | 监控、反馈、变更 | 迭代计划 | progress.md、risks.md | 运维 Agent |

## 3. 阶段门（Gate）规则

- 每个阶段结束设置**阶段门**：出口产物齐备、关键验证通过、风险受控才进入下一阶段。
- 阶段门评审要点：<按项目自定义，如：需求冻结前完成干系人确认；开发前完成设计评审；发布前完成测试准入。>

## 4. 多智能体协作流程

- **任务委派**：主 Agent 将任务委派给子 Agent，携带：目标、范围、约束、验收标准、产物路径、截止时间。
- **上下文交接**：跨 Agent 上下文通过 ref/ 文档与 doc/ 产物落档交接，避免仅靠对话传递。
- **验证门禁**：每个 Agent 交付前自验（运行测试/构建/渲染/重算），再交由下环节。
- **平台分工（多 Agent 平台）**：明确各平台（Claude Code / Cursor / Codex / OpenCode 等）负责的环节与环境，避免重复劳动与状态冲突：
